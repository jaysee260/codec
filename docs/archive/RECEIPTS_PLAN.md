# Read receipts plan: "sent / seen by"

Phases 1-6 shipped the client, phone layout, voice, threads, GIFs, E2EE and link previews. Today a sent message looks the same whether the server has it or not, and nothing shows who has read what. This feature adds the Element behaviour JC asked for ("it shows when a message is delivered and who has seen and who has not seen it"): a **sent** check on my newest message, small **read avatars** under the row each person has read up to, and a **Seen by / Not seen yet** list per message, with a **Send read receipts** setting for people who do not want to be seen. Scope source: the orchestrator's receipts brief (stakeholder: JC). Tickets: docs/archive/RECEIPTS_TICKETS.md. Criteria and testids: docs/archive/RECEIPTS_ACCEPTANCE.md. Demo: docs/archive/RECEIPTS_DEMO.md. Status: docs/STATUS.md "Read receipts". File names are `RECEIPTS_*`, not `PHASE7_*` (another open PR may take that number).

## Goals
1. **I know my message landed**: a sending indicator while the local echo is pending, a sent check once the homeserver accepted it, and the existing failed UI when it did not; identical in plain and encrypted rooms.
2. **I see who has read what, live**: avatars sit under each person's latest read row and move as receipts arrive, in the main timeline and inside threads, without a reload and without the list jumping.
3. **I can ask "who has not seen this?"**: a list per message with Seen by (name, avatar, time) and Not seen yet, reachable from the avatars and from the message actions, on desktop and phone.
4. **I can opt out of being seen**: a Send read receipts toggle that switches to private receipts, shared with Element through account data, while my own unread counts still clear.

## Product decisions (settled by the orchestrator; written down here, not reopened)
| Topic | Decision |
|---|---|
| Send status, own messages | Pending / local echo: a small "sending" indicator (hollow circle) on the row. Failed keeps the existing failed UI. Once the server has it: a "sent" check. In Matrix "delivered" == accepted by the homeserver; there is no separate delivered state. Like Element, the sent check shows only on **my newest message that nobody else has read yet**; once someone has read it the check is replaced by their read avatars. Tooltip / aria: "Sending…", "Sent". |
| Read avatars (any message) | Under the message that is each user's **latest read point**, small stacked avatars of those users (everyone except me), max 3 + "+N". Receipts that point at a non-rendered event (reaction, edit, redaction, hidden state event) attach to the nearest earlier rendered row. Avatars move as receipts move (live, no reload). Aria: "Seen by Bob, Carol". |
| Seen-by list | Hover (desktop) or tap / click (desktop click too; phone tap) on the avatars opens a list for that message: **Seen by** (name + avatar + time read, newest first) and **Not seen yet** (joined members other than me and the sender who have not read up to this message). Users with private receipts are indistinguishable from "not seen yet": that is the point. Rooms with > 50 joined members show only Seen by plus "N others haven't seen it yet"; keep it simple. The list is also reachable from the message action menu ("Seen by") so a message with zero readers can show its Not-seen list (this is how you see "who has not seen" in a quiet room). Phone: bottom sheet; desktop: popover. Escape / outside click closes. |
| "Has seen" rule | A user has seen event E iff `room.hasUserReadEvent(userId, E.id)` (SDK; covers threaded receipts and later receipts). The sender of a message has always seen it. |
| Threads | Same UI inside the thread panel, driven by threaded receipts (`thread_id` = root). Main timeline rows use main receipts. Use the SDK's thread-aware APIs (`Thread` is a receipt holder too). |
| Encrypted rooms | Receipts are unencrypted metadata in Matrix; everything works identically in E2EE rooms (local echo id is `~txn`, the decrypted event keeps its id: status must flip correctly). Undecryptable rows still get avatars. |
| Private receipts | New setting **Send read receipts** (default ON). OFF => `sendReadReceipt` sends `m.read.private` instead of `m.read` (unread counts still clear for me; others never see me). Stored in account data `im.vector.web.settings` key `sendReadReceipts` (where Element stores it, so it follows the user across Codec and Element; merge, never clobber other keys). UI: a toggle in the user settings (UserFooter area) on desktop and phone. When OFF I still see other people's public receipts (same as Element). |
| Performance | Per-row data comes from one per-timeline map (eventId -> readers) rebuilt on receipt / timeline changes, not per-row O(members x events) scans. Rooms are small (< 50) but nothing is quadratic per render. |
| Desktop "Seen by" entry (Advisor consult 2) | A direct `message-action-seen-by` button in the existing `message-actions` toolbar (6th icon, `aria-label="Seen by"`; the toolbar may wrap at the narrowest width with the thread panel open); **overflow menu deferred**. Phone: a row in `message-action-sheet`. |
| "+N" test strategy (Advisor consult 1) | Every seeded room has 4 members (3 others from alice's view). "+N" is P1: a unit / component test with 5 fake readers **and** an e2e that registers 4 throwaway users (`freshUser` in `e2e/fixtures/e2ee-api.ts`, open registration on the test Synapse), joins them to a fresh room, posts receipts via API. No 5th seeded user. See AC-R2-4. |

## Out of scope

## Risks and mitigations
| Risk | Impact | Mitigation |
|---|---|---|
| Local echo -> sent flip in encrypted rooms | The `~txn` echo is replaced by the real event id after `/send`; a row keyed on the echo id keeps "sending" | `getSendStatus` reads `event.status` (`SENDING` / `QUEUED` / `ENCRYPTING` -> sending, `NOT_SENT` -> failed, `null` -> sent); the row re-keys on `event.getId()` as today (ARCHITECTURE "do not send receipts for `~` ids"); AC-R1-2 pins the encrypted flip. |
| Receipt on a hidden event (reaction, edit, redaction) | Avatars vanish or land on the wrong row | `buildReadPoints` walks the room / thread timeline from the receipt's event backwards to the nearest displayed row; AC-R2-3 covers reaction and edit receipts. |
| Threads: main vs threaded receipts mixed | Avatars in the thread panel reflect `thread_id: "main"` reads (or the reverse) | `useReadPoints(source)` takes the `TimelineSource`; thread sources read the `Thread` holder; `hasUserReadEvent` is thread-aware in v43. Unthreaded receipts (no `thread_id`) legitimately count for threads too (spec; Advisor consult 3). AC-R6-1/2/2b. |
| `hasUserReadEvent` cost | O(members x events) per render | One map per timeline rebuilt on `RoomEvent.Receipt` and timeline change (receipt version counter in the bridge); rows read the map. |
| Setting clobbers Element's `im.vector.web.settings` | Other Element web settings lost | `setSendReadReceipts` reads the current content and merges only `sendReadReceipts`; unit test with a pre-existing foreign key. AC-R7-4. |
| Private receipts in the test server | `m.read.private` unsupported -> 400 | Synapse has supported it since 1.6x; AC-R7-2 asserts the request body / `receiptType` and that bob never sees alice. |
| Avatars appearing under the newest row move the list | Breaks stick-to-bottom (BUG-28 family) | Fixed-height avatar strip (reserve the row's bottom space or keep avatars within the row's existing padding); the BUG-28 ResizeObserver re-pins while stuck. AC-R9-1. |
| Hover popover vs click on desktop | A hover popover that also opens on click can flicker or double-open | One open state per list: hover opens, click pins, Escape / outside click closes; QA asserts a single `receipt-list` at a time. |
| Dirty seed | Other specs' receipts in `#dev` change who is "Not seen yet" | Every criterion sends its own message and asserts on its own event id; bob / carol / dave receipts are posted by the test via `ApiUser.receipt`. The seed's existing alice receipt on `#dev` #6 is irrelevant to new messages. |
| "+N" needs 4 other readers | Not reachable from the seed | Unit / component test plus an e2e with 4 throwaway registered users in a fresh room (AC-R2-4); never a seed change. |

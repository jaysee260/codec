# Local Synapse homeserver

Synapse on SQLite, server name `localhost`, client API on http://localhost:8008. No federation, no TLS, no E2EE.
One config (`homeserver.yaml` in this folder) is shared by both ways of running it.

## Commands (run from the repo root)

`scripts/hs.mjs` picks the backend: Docker when `docker info` succeeds, otherwise the WSL1 fallback
(`wsl/hs.sh`). Force one with `HS_BACKEND=docker` / `HS_BACKEND=wsl`.

| Command | Docker backend | WSL1 backend |
|---|---|---|
| `npm run hs:up` | Generates `data/localhost.signing.key` if missing, `docker compose up -d`, waits for `/_matrix/client/versions`. | `bash homeserver/wsl/hs.sh start`, waits for the same endpoint. |
| `npm run hs:down` | `docker compose down` (data kept). | `hs.sh stop` |
| `npm run hs:reset` | Down, wipe `data/`, regenerate the key, up. Follow with `npm run seed`. | `hs.sh reset` (wipes the DB + media inside the distro, keeps config, restarts). |
| `node scripts/hs.mjs logs` | `docker compose logs -f` | `hs.sh logs` |
| `node scripts/hs.mjs status` | which backend + is Synapse answering | same |

`npm run seed:reset` = `hs:reset` + `seed`.

## Files

- `homeserver.yaml` - **committed, the single config**. Generated-equivalent settings plus the
  `# --- matrix-poc overrides ---` block: open registration without verification, all `rc_*` limits at
  1000/s, presence on, `enable_authenticated_media: false` (so plain `<img src="/_matrix/media/v3/...">`
  works), `experimental_features.msc3575_enabled` (Simplified Sliding Sync; a no-op on current images).
  Paths inside point at `/data/...`: Docker mounts `./data` there; a native install symlinks it.
- `localhost.log.config` - committed. Logs to the console (`docker compose logs`).
- `docker-compose.yml` - the Docker path: one `synapse` service, `./data` + the two config files bind-mounted, port 8008.
- `data/` - git-ignored runtime data (Docker path): `homeserver.db`, `media_store/`, `localhost.signing.key`
  (regenerated by `hs:up` when missing).
- `wsl/` - the WSL1 fallback (`hs.sh`, `setup.sh`, `configure.sh`, `README.md`), for machines where
  Docker Desktop cannot start because hardware virtualization is disabled in firmware.

## Verifying

```
curl http://localhost:8008/_matrix/client/versions
curl -X POST http://localhost:8008/_matrix/client/v3/register \
  -H 'content-type: application/json' \
  -d '{"username":"smoke","password":"password123","auth":{"type":"m.login.dummy"}}'
```

## Requirements / gotchas

- Docker Desktop needs hardware virtualization enabled in firmware (WSL2 or Hyper-V backend). If
  `docker info` returns `500 Internal Server Error` and `wsl` says "virtualization is not enabled",
  enable VT-x/AMD-V in the BIOS; nothing in this repo can work around that.
- Port 8008 must be free (`netstat -ano | findstr :8008` on Windows).
- If Synapse cannot write to `data/` (Linux hosts), set `UID`/`GID` environment variables for the
  container to your user id, or `chown -R 991:991 homeserver/data`.
- `homeserver.yaml` contains three random secrets. They only protect a throw-away local server.
